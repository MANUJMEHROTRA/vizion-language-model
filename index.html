Start with the distinction

VLM is not the same as VLA

A vision-language model (VLM) takes visual input and text and usually produces text. A vision-language-action model (VLA) also conditions on robot state and predicts an action representation. A chatty visual model is not automatically a robot policy.

VLM: understand and describe

image + question → visual features + text tokens → answer tokens

Examples: image question answering, OCR, chart reading, captioning, video summarization, visual grounding.

VLA: perceive and act

images + instruction + robot state → policy → bounded action(s)

Requires robot demonstrations or interaction, embodiment-specific action semantics, feedback, evaluation, and safety controls.

The data path

Inside a typical image-conditioned decoder

1. ImageRGB pixels, resize/crop/tiles
2. Vision encoderPatch features with positions
3. Project / fuseVisual vectors meet LM width
4. Text decoderCausal self-attention + image access
5. Output tokensNext-token probabilities → answer
patches: [B, C, H, W] → [B, N, D] · words: [B, T] → [B, T, D] · logits: [B, T, vocabulary]

Architectures vary. Some insert image embeddings directly into a unified token stream; others use a resampler/projector or decoder cross-attention. High resolution increases visual tokens and often costs quadratic attention compute unless architecture or attention implementation changes that trade-off.

Embeddings, attention scores, and losses—step by step

Tokens are learned vectors, attention is a learned compatibility-and-mixing operation, and losses turn predictions into gradients. The full runnable derivations are in Notebook 09: embeddings, attention & losses.

From token ID to contextual representation

E ∈ ℝ^(vocab × d)
xₜ = E[tokenₜ] + positionₜ
Q = XWQ, K = XWK, V = XWV

The token ID is an address into an embedding table. Its selected row is learned from downstream gradients. Positional information distinguishes order. Attention and MLP layers transform this initial vector; the same token embedding can therefore acquire different contextual representations in different sentences.

Visual features follow a parallel path: vision encoder → feature tokens → learned projector to language width. Matching vector widths allows fusion, but joint training objectives—not width alone—teach compatible visual and textual meanings.

How a score becomes an attention read

S = QKᵀ / √dₖ
A = softmax(S + mask, over keys)
C = AV

Each query-key dot product is a learned compatibility score. Divide by √dₖ to control score scale as head width grows. Softmax normalizes each query row across available key positions. A causal/padding mask blocks forbidden keys before softmax. The resulting weights mix value vectors; cross-attention lets text queries read image keys and values.

Shapes: self-attention scores `[B, heads, T, T]`; text-to-image cross-attention scores `[B, heads, T_text, N_image]`.

Next-token cross-entropy

pⱼ = softmax(logits)ⱼ
CE = −log(p_correct)
∂CE/∂logitⱼ = pⱼ − 1[j = correct]

The logit at position t predicts token t+1. Teacher forcing provides true preceding tokens, while the causal mask hides future tokens. Average loss only over intended targets: padding and often prompt tokens use an ignore label such as `-100`. Inference instead conditions on generated tokens.

Contrastive alignment and other losses

sᵢⱼ = normalize(imageᵢ) · normalize(textⱼ) / τ
L = ½ [CE(s, diagonal) + CE(sᵀ, diagonal)]

Contrastive learning treats paired image/text examples as positives and other batch members as negatives. Duplicate captions can become false negatives. Matching classifiers, grounding/box losses, caption generation, and instruction tuning supervise different behaviors; a recipe may mix them with weights or train in stages.

A low loss is not proof of correct visual grounding or safe robot behavior. Check image dependence, held-out generalization, task slices, per-example failures, and (for robotics) closed-loop success and safety metrics.

From next-token probability to loss and gradient

For a correct next token with probability p, cross-entropy is −log(p). For softmax logits, the derivative for the correct logit is p−1; each incorrect class receives its predicted probability. Gradient descent raises the correct logit and lowers alternatives.

L = −log(p_correct)  ·  ∂L/∂zⱼ = pⱼ − 1[j = correct]

For this illustration, the remaining probability is divided equally among three incorrect tokens. Real models distribute it over a much larger vocabulary. During training, the loss is averaged only over valid target tokens; padding and often prompt tokens are ignored.

An interactive toy

Why patch count matters

For a square image of side H and square patch side P, the patch count is N = (H/P)². Standard full self-attention has a rough sequence-length term proportional to N². Real vision encoders use positional information and may use crops, windows, or other optimizations; this control is only a teaching aid.

Increasing image resolution or decreasing patch size can reveal detail (e.g. small text), but consumes more compute and context.

How it learns

Pretraining is a sequence of data and objectives

1

Curate paired/interleaved examples

Rights, provenance, deduplication, data quality, caption quality, language balance, privacy and split boundaries are foundational.

2

Align image and language representations

Contrastive losses (CLIP-style) pull matching image/text embeddings together and mismatches apart. This supports retrieval but does not, by itself, teach a generative assistant.

3

Train a generator to predict text

Given image features and preceding tokens, predict the next target token. Shift labels by one; mask padding and any prompt tokens that should not be supervised.

4

Instruction tune and evaluate

Use curated question-answer/instruction examples, then test OCR, grounding, reasoning, robustness, latency, and failure cases separately.

Contrastive objective

Sᵢⱼ = imageᵢ · textⱼ / τ
loss = (CE(S, diagonal) + CE(Sᵀ, diagonal)) / 2

Autoregressive objective

L = − Σₜ log p(yₜ | y<ₜ, image)

Loss is not a quality score. Held-out behavior and data integrity are essential.

Adapt without starting over

Fine-tuning, freezing, and LoRA

Full fine-tuning

Update all or most weights on task data. Flexible and potentially data-hungry; higher training/optimizer memory and greater risk of forgetting prior capabilities.

Partial fine-tuning

Freeze vision or language modules and train a projector/head or selected blocks. Cheaper, but a frozen representation may not adapt enough.

LoRA: a low-rank update

W′ = W + ΔW
ΔW = (α / r) · B · A
rank(ΔW) ≤ r

Freeze base W; train small matrices A and B. The update adds few trainable parameters. LoRA is an adaptation method, not quantization; serving overhead depends on whether updates are merged and on the runtime.

Study the complete manual PyTorch adapter and optimizer loop in Notebook 05. No high-level training wrapper is used in the curriculum.

A moving target

Model landscape and small-model choices

Evidence snapshot checked on 2026-10-17. “Best” depends on the task, hardware, license, resolution, and protocol. Candidates below are families to benchmark, not a universal rank. Leaderboards are dynamic; benchmark figures from model cards are often self-reported.

General multimodal candidates: Qwen3.5 includes compact sizes; Qwen3-VL cards describe spatial/video/OCR capabilities. Compare task-sliced scores and verify hardware/runtime support. Do not infer action-policy ability from VQA performance.

Small language models (text-only)

Qwen3 0.6B/1.7B and SmolLM2 family sizes are useful for lightweight text tasks, instruction parsing, or baselines. Without a visual encoder, they do not directly see images.

Small multimodal models

Gemma 4 E2B/E4B, Qwen3.5 4B, and SmolVLM2 offer image input at smaller scales. Check quantized latency and quality on your own camera data. Small does not imply safe, reliable, or real-time.

Application path · SO-101

Make the VLM a component, not the safety layer

Camera(s)RGB + timestamp
Task instructionHuman-defined goal
Policy / VLAAlso uses joint state
Safety controllerLimits, watchdog, stop

For the SO-101, first calibrate motor IDs, joint ranges, direction, zero offsets, camera and state timing. Record teleoperated demonstrations at episode granularity. Behavior cloning is a safer baseline than online exploration. A VLM can help interpret a scene or instruction, but a deterministic controller must validate all actions.

Safe progression

  1. Offline dataset and data-quality checks
  2. Behavior cloning; held-out episodes
  3. Simulation and latency/failure tests
  4. Workspace limits, low speed, human E-stop
  5. Only then consider constrained RL

Never let a language model's free-form answer directly command servos. Clamp and validate actions; stop safely on stale observations, NaNs, deadline misses, communication faults, or unexpected contact.
